# companion projects

1. Read relevant local notes and the task source. Clarify the outcome, scope, owner, success measure, deadline and dependencies where needed.
2. Create personal/projects/<safe-name>/PROJECT.md using templates/project.md. Scope names must not escape personal/ or collide with existing unrelated projects.
3. Keep status and milestones in the project note, decisions in linked vault notes, and tasks in personal/todo/tasks.json with this project name. Do not create a competing task database.
4. For work in external repositories or systems, inspect permissions and obtain explicit approval before writes. The project skill does not authorise pushes, messages, purchases or deployments.
5. Update progress from evidence. Separate completed work, blocked work and planned work. Do not report a milestone complete without its acceptance evidence.
6. Save outputs under that project or personal/outputs, update handover, and cite paths in the response.

Success: a new chat can identify the project's objective, current state, evidence and next action.
