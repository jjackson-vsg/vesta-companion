# Decision Deck

Read system/COMPANION.md first.

1. Confirm the decision, audience, supplied evidence and desired meeting outcome. Separate an exploratory discussion from a decision request.
2. Create conclusion-led sections covering purpose, current evidence, options/trade-offs, recommendation and a clear decision register. Use only the owner's supplied operating/financial frame; do not invent a company's metrics.
3. Keep evidence traceable and distinguish facts, assumptions and proposals. Describe simulated or prototype material as such.
4. Produce a local, self-contained HTML file in personal/outputs/decks with system fonts, readable contrast, restrained generic styling, keyboard navigation and print support. No remote libraries, fonts, telemetry or embedded work-account links containing secrets.
5. Preserve previous versions. Check viewport fit, keyboard navigation, printable output, source notes and whether each requested decision is clear. Report untested aspects honestly.
6. Do not send, publish or present it externally. Other formats are optional when the owner asks and suitable tools exist.
